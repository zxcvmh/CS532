# Agent team harness v3 — design (2026-11-16)

Status: DRAFT for human approval. Nothing is built until approved. Source of the idea: Lauren Tan, "All Code Is
Slop (Except Mine)", AI Engineer CODE 2026 (summary page read; full transcript NOT read).

## Intent and why
Two goals, in the human's words: (1) save tokens, (2) make the agents behave in a controlled way. Plus a
human-in-the-loop (HITL) path, because the human's task descriptions and context can be incomplete.
Lauren Tan's rule applied here: when an agent repeats a mistake, do not add another sentence to CLAUDE.md /
AGENTS.md; move the correction into something harder to ignore (a permission rule, a hook, an executable check).
Prose stays only for judgment that cannot be encoded.

Evidence that prose rules fail in this repo: the assistant ran `sudo` over SSH despite "never SSH"; `git add -u`
swept unaudited work into a commit; `verify_agent_integrity.py` prints "ZERO-HALLUCINATION" with a missing target;
the MEAS-01 validator checked `t[-1]-t[0]` and let a 12 s hole through.

## Measured baseline (2026-11-16)
`TICKETS.md` 56.6 KB (~14k tokens), `STATE.md` 51.8 KB (~13k tokens), `supervisor.md` 11.4 KB, `AGENTS.md` 6.5 KB,
stale root `handoff-cs532-jetbot.md` 17.4 KB. A coder that needs one ticket reads the whole 14k-token file.
Existing machine enforcement: one `permissions.deny` block in `.claude/settings.json`; no hooks.

## Goals / non-goals / anti-goals
Goals: coder context for one ticket <= 40 % of today's; every mistake already made has an executable guard;
an agent that lacks context stops and asks instead of guessing; each phase has a number that proves it worked.
Non-goals: touching robot code, the acceptance thresholds, or the locked tests; replacing Antigravity; building an
orchestration framework (approach C was rejected).
Anti-goal: a harness so heavy it eats the demo schedule (freeze 2026-12-14). Any phase that delays a coder ticket
(SLAM-09, IL-04/05) is paused.

## Constraints
- `STATE.md` is an append-only ledger (global rule: never truncate or rewrite audit history). It is NOT split or
  trimmed; sessions read a short digest instead.
- Claude Code hooks and `permissions` bind only Claude sessions. The coders run in Antigravity (Gemini Flash) and
  are NOT bound by them. For them the guard is a script the Supervisor and the auditor run (plus read-only files).
- Robot-side code stays Python 3.6 compatible; no new dependencies (stdlib only).

## Approaches considered
A. Layered and measurable (CHOSEN by the human). B. Token cut only (cheap, changes no behaviour). C. Rewrite
infrastructure with machine-readable tickets and an orchestrator script (strongest control, too risky before the demo).

## Design (approach A, four phases, each ends with a number)
1. **Context diet.** (a) `agents-doc/tickets/TK-*.md`, one file per ticket, copied verbatim from `TICKETS.md`;
   `TICKETS.md` becomes an index (id, role, status, one line, link). The 4 slash commands and `AGENTS.md` /
   `.agents/rules/` point at the per-ticket file. (b) `scripts/context_cost.py`: prints bytes/4 of what each role
   loads at start (supervisor, auditor, each coder). (c) `agents-doc/STATE_DIGEST.md`: <= 2 KB, current decisions
   only, regenerated by the Supervisor at the session end; the ritual reads the digest, not 13k tokens of ledger.
   (d) stale `handoff-cs532-jetbot.md` moved to `docs/handoffs/archive/` (human decides). Done when:
   `context_cost.py` shows coder load down >= 60 % and supervisor start-up <= 6k tokens.
2. **Hard guards for the mistakes already made** (Claude side, `.claude/settings.json`): deny `git add -u|-A|.`,
   `git push`, `git reset --hard`, edits to `LOCKED_PATHS.txt` entries; `ask` for `ssh|scp|rsync` to the Jetson and
   anything that starts the bridge or motors. Done when: a throwaway test run triggers each rule once.
3. **`scripts/check_ticket.py TK-ID`** — the mechanical half of the auditor, stdlib only, exit non-zero on failure:
   changed paths vs the ticket's Allowed files, LOCKED_PATHS hits, new `skip` / loosened asserts / `except: pass`
   in the diff, numeric literals near speed/pwm/turn outside `robot_dynamics.json`, dead-folder paths, then the
   ticket's acceptance + regression commands with the metric printed. The auditor reads its output and spends
   tokens only on judgment (units/frames, test integrity beyond grep, research citations). Replaces the misleading
   `verify_agent_integrity.py` (deleted or made to call this). Done when: it reproduces the known results on
   TK-MEAS-01 attempt 1 (scope REJECT) and TK-SLAM-09 (13/13), and fails on a planted out-of-scope edit.
4. **HITL gate.** Each ticket gets two fields: `Assumptions` (what the Supervisor filled in) and `Needs-human`
   (open questions). A ticket may be marked READY only with `Human-approved: <date>` under Assumptions
   (`check_ticket.py --ready` enforces it). A coder who hits missing context stops and writes
   `agents-doc/needs-human/TK-ID.md` (question, what it tried, a default it proposes); `check_ticket.py` fails while
   one is open. Hardware or outward actions stay human-gated via phase 2's `ask` rules. Done when: a planted
   missing-context ticket makes a coder stop with a needs-human file instead of guessing.

## Decided by the human / my calls
Human: approach A, order of phases, HITL for incomplete context. My calls (to be checked): stdlib-only scripts;
STATE.md untouched (digest instead of trimming); ticket split by copy, not rewrite; `permissions` before hooks
(simpler, no code), hooks only if a rule needs logic; the stale root handoff is archived only with human approval.

## Left to the builder
File layout details, the exact deny/ask patterns, the regexes in `check_ticket.py`, how the digest is generated.

## Builder check (I read this as the builder; no subagent was spawned)
- "How does a coder not read the old TICKETS.md?" — answered: index + links, and `context_cost.py` measures it.
- "Do the guards also stop Antigravity?" — No. Stated in Constraints; only `check_ticket.py` + auditor cover it.
- Open for the human: whether the digest may include a short "do not repeat" list drawn from the ledger.
